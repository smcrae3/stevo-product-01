# First-Reply Rapid Response Pack (Internal)

Use this the moment a real prospect replies to outreach, comments on
Fiverr/Upwork, or asks a question about Product-01. This is internal
guidance only — never paste it verbatim to a prospect.

**Caveat:** this repository contains no documented Product-01 feature
list or approved messaging, so the "safe response strategy" lines below
use generic, guardrail-compliant placeholders in `[brackets]`. Replace
each bracket with Steven's actual approved wording before use. Never fill
a bracket with a guessed capability — leave it blank and ask Steven
first if unsure.

Guardrails that apply to every scenario below — never claim: SMS, voice
AI, CRM integration, automatic booking, automatic scheduling, automatic
quoting, automatic dispatch, guaranteed response time, ROI, conversion
increase, booked-job increase, or paying-customer deployment.

---

## 1. "Tell me more."
- **Intent:** low-commitment curiosity, not yet a buying signal.
- **Best next action:** short value framing + one clarifying question.
- **Safe response strategy:** "[One sentence on the problem Product-01
  addresses — missed/slow lead response], and [one sentence on what it
  does]. What's your current process when a new lead comes in?"
- **Offer demo:** no, not yet — earn it with one more exchange first.
- **Discovery question:** yes — how they currently handle inbound leads.
- **Disqualify:** no.

## 2. "How does this work?"
- **Intent:** genuine interest, wants mechanism.
- **Best next action:** plain-language walkthrough, then offer the demo.
- **Safe response strategy:** describe only what's verified/approved —
  do not describe internal automation steps you can't confirm are live
  in the current build. Default to: "[High-level, non-technical
  explanation approved by Steven]." Then: "Happy to show you the actual
  demo video if that's easier than me typing it out."
- **Offer demo:** yes.
- **Discovery question:** optional — trade type, lead volume.
- **Disqualify:** no.

## 3. "How much?"
- **Intent:** pricing-qualified, ready to evaluate cost.
- **Best next action:** state the founding-pilot price plainly, frame as
  limited/early.
- **Safe response strategy:** "$199 for a founding pilot — [scope of
  what that includes, per Steven's approved terms]." Do not improvise
  scope not already approved in writing.
- **Offer demo:** yes, alongside the price.
- **Discovery question:** optional — timeline to start.
- **Disqualify:** no.

## 4. "Do you have a demo?"
- **Intent:** wants proof before committing time/money.
- **Best next action:** send the approved unlisted demo link.
- **Safe response strategy:** share the link, one sentence of context on
  what they'll see, invite questions after.
- **Offer demo:** yes — this is the ask.
- **Discovery question:** no, not needed here.
- **Disqualify:** no.

## 5. "We already use a CRM."
- **Intent:** possible objection, possible non-fit, possible fine.
- **Best next action:** clarify whether Product-01 competes with or sits
  alongside their CRM — do not claim integration capability that isn't
  confirmed.
- **Safe response strategy:** "Totally fine — Product-01 isn't a CRM
  replacement, it's [approved positioning re: what problem it solves
  regardless of CRM]. Which CRM are you on, out of curiosity?"
- **Offer demo:** optional, if they stay engaged.
- **Discovery question:** yes — which CRM, and where leads currently
  fall through.
- **Disqualify:** only if their stated need is explicitly CRM
  replacement/integration, which is out of scope — say so honestly.

## 6. "Does it text customers?"
- **Intent:** feature question, guardrail-relevant.
- **Best next action:** answer honestly per current guardrails — do
  NOT claim SMS capability.
- **Safe response strategy:** "[Accurate current answer — if SMS is not
  a live feature, say so plainly rather than imply it]. Here's what it
  does do today: [approved feature description]."
- **Offer demo:** yes, to show what it actually does.
- **Discovery question:** ask why texting matters to them — may reveal
  the real underlying need.
- **Disqualify:** no, unless SMS is a hard requirement they won't move
  without — say so honestly rather than overpromise.

## 7. "Can it book appointments?"
- **Intent:** feature question, guardrail-relevant.
- **Best next action:** same as above — never claim automatic booking.
- **Safe response strategy:** "[Accurate current answer on what happens
  after a lead comes in, without implying automatic booking/scheduling
  unless Steven has explicitly confirmed that's live]."
- **Offer demo:** yes.
- **Discovery question:** what their current booking process looks like.
- **Disqualify:** only if automatic booking is a hard requirement and
  it's genuinely not there — say so honestly.

## 8. "Can it work with my website?"
- **Intent:** technical/compatibility question.
- **Best next action:** confirm what's actually been tested/approved;
  don't promise integration with an unverified stack.
- **Safe response strategy:** "[Approved answer on compatibility/setup
  requirements]." If unsure, say you'll confirm rather than guess.
- **Offer demo:** yes.
- **Discovery question:** what platform their site/intake runs on.
- **Disqualify:** no, unless a hard technical blocker surfaces.

## 9. "I'm interested."
- **Intent:** buying signal — highest priority reply.
- **Best next action:** move to demo + pricing + next step immediately,
  respond fast.
- **Safe response strategy:** thank them, send the demo link, state the
  $199 founding pilot price and what happens next if they want in.
- **Offer demo:** yes.
- **Discovery question:** optional — timeline, but don't slow the close
  down with unnecessary questions.
- **Disqualify:** no.

## 10. "Not interested."
- **Intent:** decline.
- **Best next action:** graceful close, no pressure, leave door open.
- **Safe response strategy:** "No problem at all, appreciate you taking
  a look. If anything changes down the line, feel free to reach out."
  Do not re-pitch.
- **Offer demo:** no.
- **Discovery question:** no.
- **Disqualify:** yes — mark closed/not interested in the pipeline
  tracker (once one exists — see NEW-THREAD-HANDOFF.md).
